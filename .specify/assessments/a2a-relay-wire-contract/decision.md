## Verdict & Rationale

**Go.** Problem validity and evidence strength are both adequate, and concept.md recommends a specific option (B). The idea is worth specifying because the alternative to specifying it is a ratified feature that stays dark forever: the current wire has zero implementations and there is no path to any without either this change or a per-agent shim treadmill (Options A and C). The verdict is deliberately not "strong" anywhere except strategic fit — demand is a single owner's intent, adoption figures are partly unverified, and the one property 007 treated as non-negotiable (single external start on replay) is weakened to a two-tier guarantee by the standard itself. Those are acknowledged costs, not blockers: the owner accepted the two-tier guarantee explicitly on 2026-09-03, the feature remains rollout-OFF so no user is exposed until observed demand justifies widening, and the appetite is bounded. The two `unknown`-class gaps (Fly capacity, cloud credential schemes) do not block specification; they are carried forward with the stage that must answer them. Had the owner not resolved the guarantee-tier and admission questions, this would have been `needs-clarification` back to research.

## If go — Handoff to `/speckit-specify`

- **Problem**: BrainBuddy's bring-your-own-agent relay promises a provider-agnostic hand-off but speaks a bespoke envelope no agent implements, so zero agents are reachable; the agents its users operate already speak the Linux Foundation A2A v1.0 standard that BrainBuddy does not.
- **Chosen approach**: concept.md Option B — replace the 007 wire entirely with A2A v1.0 (bearer or API-key auth over public HTTPS); an optional BrainBuddy A2A extension gives extension-capable agents the strong single-start guarantee; all other conforming agents are admitted with BrainBuddy-side deduplication before any resend and an honest, visible residual duplicate-start disclosure; run state is observed by a BrainBuddy background observer and mapped onto the existing 007 projection, with agent push as an accelerator only; the generic HTTP connector is removed and custom agents connect through an A2A SDK. Delivery constraints from the owner: this is new feature **014** (unclaimed on every git ref as of 2026-09-03), superseding the 007 wire contract while 007 stays ratified history; all work lands on branch `claude/agent-delegation-yv9auj` and PR #192 with any Spec Kit feature branch kept local; appetite medium (weeks), no calendar deadline; release through exact-SHA dual review, green CI and ASK authority as for 007; rollout stays OFF until separately authorised.
- **In scope / out of scope**: In — any A2A v1.0 agent reachable over public HTTPS with bearer or API-key auth, self-hosted (Hermes/OpenClaw class) and cloud-hosted (Bedrock AgentCore, Azure AI Foundry, Google ADK); the relay working against the **unmodified** Hermes A2A plugin (blocking reply up to 300 s, terminal-only push); preservation of every wire-independent 007 guarantee (consent preview, reauthentication, sealed secrets, retention, disconnect, rollout-OFF semantics, purge, FR-011 honesty, FR-012 no Task mutation); one projection on web and iOS. Out — OAuth2/mTLS; any 007 envelope compatibility or the generic HTTP connector; any dependency on an upstream Hermes patch; BrainBuddy as an A2A server; discovery/registries/marketplace; private-network destinations; streamed/rich progress rendering; cancellation beyond what the agent supports; multi-agent chains, billing, templates, organisation policy; Task classification/verification/auto-completion; protocol versions other than v1.0.x.
- **Success metrics**: (1) at least two unmodified third-party runtimes — the Hermes A2A plugin and an official a2a-sdk sample agent — complete an automated end-to-end hand-off through **Agent reported complete** (baseline 0); (2) zero BrainBuddy-specific code on the agent side (baseline: a full shim, never written); (3) three identical confirmation/dispatch replays produce exactly one external task and one Task-linked run per reference runtime (baseline: proven only against an in-repo fake); (4) the 007 SC-003 security suite passes on the new wire with zero accepted state changes and zero secret disclosure; (5) web and iOS render the same projection for every SC-002 state against both runtimes; (6) qualitative: residual duplicate-start risk is visible before confirmation for agents without the extension, and none is presented as guaranteed; (7) delivered within the medium appetite through the 007 landing gates with rollout OFF.
