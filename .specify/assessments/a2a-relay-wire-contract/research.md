# Idea Research: A2A v1.0 as the wire contract for the external-agent relay

- **Slug**: a2a-relay-wire-contract
- **Created**: 2026-09-03
- **Evidence confidence (overall)**: medium

Idea under research: replace the bespoke connector envelope of feature 007 (`PROTOCOL_VERSION = "2026-08-09"`: `capabilities`, `start`, `reply`, `cancel` plus HMAC-signed run events) with the Linux Foundation Agent2Agent (A2A) protocol v1.0, keeping BrainBuddy's product guarantees (consent manifest, reauthentication, sealed secrets, honest projection, retention) on top.

No `intake.md` exists for this slug; the idea was supplied directly. Prior-art evidence below is the first evaluation of A2A recorded anywhere in this repository.

## Users & Demand

- Stated demand is internal and singular: during the 007 interview Max resolved "begin with a named Hermes/Claude integration" versus "the product should work with any user-operated cloud agent" as "provider-agnostic BYOA protocol; Hermes remains only the reference connector". — [source: specs/007-external-agent-relay/intake.md, contradictions table] (confidence: high, cited). This is a stated want, not observed behaviour.
- Observed demand is zero: the relay module is on `origin/main` behind the Admin-Portal flag `external_agent_relay`, rollout OFF, and no connector implementing the bespoke envelope exists inside or outside the repository. — [source: `git ls-tree origin/main backend/app/modules/agents/`; docs/external-agent-relay-release.md; backend/app/core/config.py] (confidence: high, cited).
- Demand for A2A among personal-agent operators exists in the Hermes community: the plugin's design traces its requirements to a cluster of issues (#514, #689, #4135, #7517, #8948, #11025, #14559, #23871, #25176, #56434, #56435). — [source: hermes-agent `plugins/platforms/a2a/DESIGN.md`, "Requirements traced to the cluster"] (confidence: high that the demand existed there; medium that it transfers to BrainBuddy users).
- Further Hermes issues requesting A2A (#4454, #7708, #42349) appear in search results. — [source: search snippet, github.com issue titles, pages not fetched] (confidence: medium).
- Who BrainBuddy's BYOA users are and which agent runtimes they operate (personal Hermes/OpenClaw-class agents versus enterprise-hosted ADK/AgentCore agents) is unknown; no tickets, interviews or usage data exist. — ASSUMPTION (confidence: low).

## Prior Art

- Internal: the 007 envelope is a hand-rolled JSON contract over authenticated HTTPS: a `capabilities` probe that must return `idempotent_start: true` (else the connection is `unsupported`), `start(run_id, task_id, idempotency_key, title, details, context[], reporting{...})`, `reply`/`cancel` with `command_id` echo, and inbound events signed as `v1=<hex HMAC-SHA256>` over `timestamp + "." + raw_body` with `event_id` and strictly increasing `run_version`. — [source: backend/app/modules/agents/connector.py, domain.py, service.py] (confidence: high, cited).
- Internal: A2A was never evaluated. A repository-wide search for "a2a", "agent2agent", "agent card" and "json-rpc" matches only `package-lock.json` noise; `specs/007-external-agent-relay/` has no `research.md`; `.specify/assessments/` did not exist before this file. — [source: repository grep on 2026-09-03] (confidence: high, cited).
- Internal timeline: 007 baseline ratified 2026-08-09 (SHA-256 `f3cf461f…`), amendments semantically approved 2026-08-11; landing, deploy and rollout remain separately governed. — [source: specs/007-external-agent-relay/spec.md; ratification-provenance.md] (confidence: high, cited).
- Internal: 007's backlog explicitly defers "more reference connectors", "multi-agent fan-out, routing, delegation chains" and "connection templates"; none of these name a standard protocol. — [source: specs/007-external-agent-relay/backlog.md] (confidence: high, cited).
- External, the standard: A2A v1.0.0 was tagged 2026-03-12 and v1.0.1 on 2026-05-26; v1.0 introduced 16 breaking changes over v0.3.0 (enum casing, removal of `kind` discriminators, renamed operations, merged push-config types, new `ListTasks`, per-interface protocol versions, JWS-signed Agent Cards, extension mechanism with `required` declarations). — [source: a2aproject/a2a CHANGELOG.md, docs/whats-new-v1.md] (confidence: high, cited).
- External, announcement history: Google announced A2A on 2025-04-09 with 50+ partners and donated it to the Linux Foundation on 2025-06-23. — [source: search snippets of linuxfoundation.org and hpcwire.com press coverage, pages not fetched] (confidence: medium).
- External, consolidation: IBM's ACP "joined forces with A2A under the Linux Foundation's LF AI & Data" on 2025-08-29. — [source: link text in a2aproject/a2a docs/partners.md pointing at lfaidata.foundation, page not fetched] (confidence: medium).
- External, positioning: A2A is agent-to-agent; MCP is agent-to-tool; the project documents them as complementary. — [source: a2aproject/a2a docs/topics/a2a-and-mcp.md, README.md] (confidence: high, cited).
- External, Hermes: earlier standalone-server attempts (#4135, #4948, #4952, #11025) were superseded by a zero-core-edit plugin built on `ctx.register_platform()`; the plugin serves the JSON-RPC binding only via stdlib `http.server`, keeps its task store in memory bounded to 500 entries, fails orphaned tasks after 5 minutes, and lists "true task abort" as out of scope. — [source: hermes-agent `plugins/platforms/a2a/DESIGN.md`, adapter.py, protocol.py] (confidence: high, cited).
- External, Hermes positioning: A2A is recommended for crossing process, machine or framework boundaries; same-machine work uses in-process `delegate_task` or the kanban board. — [source: hermes-agent `website/docs/user-guide/messaging/a2a.md`, `features/delegation.md`] (confidence: high, cited).

## Data & Constraints

- Code footprint: the relay module is 5,485 lines; the wire-specific part (connector.py, headers.py, inbound event models, the ingest path, the reporting-instructions text) is about 719 lines, roughly 13%. Product-guarantee layers dominate: service.py excluding the wire path about 2,068 lines, repository.py 1,343, egress.py 507, secrets.py 348. — [source: `wc -l` over backend/app/modules/agents on 2026-09-03] (confidence: high, cited).
- Runtime parameters: connector timeout 10 s (max 120 s), reporting window 3,600 s, stale threshold 7 days, content retention capped at 30 days, retention sweep every 60 s on an existing background maintenance thread. — [source: backend/app/core/config.py `AgentRelaySettings`; backend/app/main.py] (confidence: high, cited).
- A2A v1.0 facts relevant to 007 requirements:
  - `SendMessage` "MAY be idempotent; agents may utilize the messageId to detect duplicate messages" (§3.3.1). 007 FR-006 requires connector-side deduplication as a hard precondition. — [source: a2aproject/a2a docs/specification.md; specs/007 spec.md] (confidence: high, cited).
  - Push notifications: the server MUST authenticate to the webhook per `TaskPushNotificationConfig.authentication`; delivery is at-least-once, duplicates may occur, clients SHOULD process idempotently; timestamps and nonces/`jti` for replay protection are SHOULD-level guidance. 007 FR-009 makes freshness, unique event id and monotonic version MUST. — [source: docs/specification.md "Server Guarantees"; docs/topics/streaming-and-async.md "Security Considerations"] (confidence: high, cited).
  - `SendMessageConfiguration.return_immediately` makes the call non-blocking; `ListTasks` filters by `context_id`, `status` and `status_timestamp_after`; streams MUST preserve event order; `Task` carries no monotonic version, only `status.timestamp`; terminal tasks reject further messages. — [source: docs/specification.md; specification/a2a.proto] (confidence: high, cited).
  - Webhook URL validation against SSRF is SHOULD-level in A2A; 007 FR-004 mandates HTTPS, public-address-only egress and DNS pinning regardless of protocol. — [source: docs/topics/streaming-and-async.md; specs/007 spec.md] (confidence: high, cited).
- Hermes plugin deviations from the spec that touch 007 requirements: no handling of `return_immediately` (every `SendMessage` blocks up to `A2A_REPLY_TIMEOUT`, default 300 s, and returns FAILED on timeout); push only on terminal transition, once, no retry, HMAC-SHA256 over sorted JSON without timestamp or nonce, secret defaulting to the bearer token; no `messageId` deduplication; `stateTransitionHistory: false`; `CancelTask` marks canceled without aborting the live turn. — [source: hermes-agent adapter.py, security.py, protocol.py, DESIGN.md] (confidence: high, cited).
- Governance: the 007 baseline is ratified by exact bytes; any wire-contract change is an amendment needing Max's approval, and landing still needs dual review on the exact SHA, CI and ASK merge authority. — [source: specs/007-external-agent-relay/ratification-provenance.md] (confidence: high, cited).
- Compliance obligations unchanged by the choice of wire: FR-003 secrets, FR-015 retention, FR-016 disconnect, FR-019 rollout-OFF semantics, account purge. — [source: specs/007 spec.md] (confidence: high, cited).

## Evidence Against the Idea

- The standard does not guarantee the one property 007 treats as non-negotiable: single external start on replay. A2A leaves `SendMessage` idempotency optional, so SC-001 and AC-009 cannot be delegated to the protocol; they would need an A2A extension or client-side deduplication, and agents that do not implement the extension would run in a degraded mode. — [source: docs/specification.md §3.3.1; specs/007 spec.md] (confidence: high, cited).
- A2A has no monotonic task version and push delivery is at-least-once with duplicates, so the FR-009 ordering guarantee would have to be synthesised on BrainBuddy's side from polling snapshots. — [source: docs/specification.md; specification/a2a.proto] (confidence: high, cited).
- The reference personal-agent implementation (Hermes) deviates from the spec exactly where 007 cares: blocking calls, weak push signing, no deduplication, in-memory task store. "Any A2A agent works out of the box" is not true for the one runtime 007 names as its reference connector. — [source: hermes-agent adapter.py, security.py, DESIGN.md] (confidence: high, cited).
- The standard is young and has churned: 16 breaking changes between v0.3.0 and v1.0.0, a v1.0.1 within eleven weeks, and Hermes still answers legacy pre-1.0 method names. Further breaking revisions are plausible. — [source: CHANGELOG.md; hermes-agent adapter.py aliases] (confidence: high that churn happened; medium as a forward projection).
- There is no observed demand from BrainBuddy users; the feature has never been rolled out and has zero connectors. The investment would rest on a single stated intent from the 007 interview. — [source: intake.md; release doc] (confidence: high, cited).
- Rework is not trivial despite the 13% figure: a JSON-RPC client, a long-lived polling or stream-holding worker, a rewritten inbound path for A2A payloads, re-running the SC-003 security suite and SC-008 barrier tests, a new review campaign and re-ratification. — [source: line counts above; specs/007 spec.md SC-003, SC-008] (confidence: medium; effort beyond the counted lines is an ASSUMPTION).
- Adoption evidence is enterprise-centric (hyperscaler platforms, orchestration frameworks); evidence for the personal-agent segment BrainBuddy's BYOA story targets is thin and partly contradictory. — [source: partners.md; search snippets] (confidence: medium).
- A2A does not remove the network friction 007 already has: a home-hosted agent still needs public HTTPS to satisfy FR-004, and A2A additionally expects `POST /` plus a well-known Agent Card path at the agent origin. — [source: specs/007 spec.md FR-004; hermes a2a.md; docs/specification.md] (confidence: high, cited).
