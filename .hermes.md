# Hermes project overlay

This file applies only when BrainBuddy is opened through Hermes Agent. It does
not change the portable repository rules used by developers, Claude Code,
Codex, or other standalone agents.

## Base repository rules

Before doing work, read `AGENTS.md`, `.specify/memory/constitution.md`, the
relevant accepted ADRs, and any feature artifacts under `specs/`. Those files
remain authoritative for product behavior, architecture, tests, security, and
release safety.

The presence of this file, the `spec-driven-kanban` plugin, a Hermes board, or
`.specify/workflows/` does **not** automatically enroll ordinary repository
work in the managed workflow.

## Execution modes

### Ordinary Hermes work

Unless the task is explicitly activated as a managed outcome, follow the same
portable workflow as a standalone agent:

- use the normal Spec Kit artifacts and task format;
- do not call `spec_workflow_*` tools;
- do not create managed QA/release lanes or plugin receipts;
- do not require Claude Code merely because Hermes is running;
- preserve the repository's worktree, TDD, review, CI, landing, and release
  gates.

### Opt-in managed outcome

Apply the Hermes managed-delivery overlay only when at least one explicit
activation signal is present:

- the user asks to run the outcome through `spec-driven-kanban`; or
- the assigned root task contains
  `workflow_contract: spec-driven-delivery/v1`; or
- the task is an existing plugin-managed root/lane with a valid workflow
  manifest.

For an activated managed outcome:

1. Read ADR-0010 and `docs/spec-driven-kanban.md` before mutating workflow
   state.
2. Load `spec-driven-kanban:spec-architect` on the root outcome and follow
   `state -> reconcile -> allowed_next`.
3. Keep canonical product planning under `specs/NNN-feature/`. Pass explicit
   `spec_path`, `plan_path`, and `tasks_path` to `spec_workflow_start`.
4. Apply the managed task annotations and lane/evidence rules from the runbook
   only to that enrolled outcome. Never make those annotations a repository-wide
   Spec Kit requirement.
5. Let `spec_workflow_build_handoff` create managed delivery, QA, integrated-QA,
   and release lanes. Do not create sibling lanes manually.
6. Use Claude Code CLI as the product-code writer for signed implementation
   scopes; Hermes independently inspects the diff, runs checks, and validates
   exact-SHA evidence.
7. Product/privacy/legal/cost/safety/irreversible authority decisions require
   the documented human decision receipt. Technical choices remain internal.
8. ADR-0008 remains authoritative for commit, push, landing, ruleset, secret,
   deployment, and rollback authority.

If activation is ambiguous, remain in ordinary mode; do not silently convert
ad hoc work into a managed outcome.
