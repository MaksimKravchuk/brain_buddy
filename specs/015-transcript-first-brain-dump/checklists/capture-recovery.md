[Completeness, Spec §FR-005, US2 #3/#5] — Web: the save control is hidden and discard returns to a fresh recording; mobile: the confirm control is hidden.
- [ ] CHK004 Are loading-state requirements defined for a persisted recording opened cold (reload, shared link, app reopened) on web and mobile? [Gap, Spec §FR-008] — **Open**: no FR asks for a loading state. `design.md` had to introduce D-05.a/b and M-03.a citing FR-008, which speaks only of what a resumed *recording* screen restores. - [ ] CHK005 Is the retryable-failure path of the recovery itself specified — what the owner sees and may do when the browser-transcript extraction fails retryably rather than terminally, and how that squares with "one attempt per recording"? [Gap, Spec §FR-009, Clarifications #3, US3 #3] — **Open**: the spec covers success and terminal failure only. The ADR-0002 amendment ("One shot") and `plan.md` A3 ("Retry of the recovery") route a retryable preview failure through the ordinary `retry` command, bounded by `BRAIN_BUDDY_VOICE_MAX_OPERATION_RECOVERIES=2` (`.env.example`); `research.md` R-06 says this "is what one attempt means at the operation level". None of that is in `spec.md`, and D-04.b's retry copy ("retried from the accurate transcript") does not fit a preview retry. Define "attempt" (one owner-chosen recovery stage, retryable within the existing budget) or forbid the retry.
- [ ] CHK006 Does the spec state that the recovery is *not* offered once an accurate transcript exists — a terminal task-extraction failure after successful transcription — or is that left to be inferred from "browser transcript text present"? [Gap, Spec §FR-009, §Key Entities "Transcript segment"] — **Open**: the ADR-0002 amendment is explicit ("it is not offered while an accurate transcript stands: accurate-STT utterances supersede the preview segments, so a reconciler-stage failure after a successful transcription still offers cancel only") and `data-model.md` §2 pins "a superseded preview segment is never recovery input". `spec.md` says only that a superseded segment is not read out. A tester reading spec.md alone can construct "preview captured, transcription succeeded, extraction failed terminally" and expect the action; the system offers cancel.
