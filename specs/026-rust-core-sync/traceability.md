# Traceability: 026-rust-core-sync

Graded 2026-10-14 against `origin/main` 3764dfc6 by `acceptance-auditor`. CI run 38530856766 is green at that SHA.

**Updated after the code-only gap closure (post-audit, same day).** Rows 026-FR-002, 026-FR-016, 026-FR-021, 026-SC-003, 026-SC-006, 026-SC-008 and US5-AS4 below reflect the closure: the auditor's grade of the other rows is unchanged. The verdict itself is not changed by this update; the device and PostgreSQL blockers remain.

Status values:
- `covered`: a named, executable 026-qualified test exercises the behavior on the current SQLite store.
- `weak`: a test exists but does not exercise the claim.
- `missing`: no test exists.
- `pending-device`: the criterion is a device measurement or a device UX judgement, and the reference-device pilot (iPhone 11 / MacBook Air M1, `evidence/apple-pilot.md`) has not run.
- `pending-pg`: the logic is covered on SQLite, but the PostgreSQL slices PR-55/56/57 that `tasks.md` binds to this id have not landed.
- `rehearsal-only`: the number was measured only in `evidence/rehearsal-2026-10-14.md` (M4 / Simulator), which is explicitly not reference evidence.

PR-54 lists every FR and SC, so every row also depends on the pending Q01–Q12 pilot. A row is marked `pending-device` only where the criterion itself is about the device.

Layer abbreviations: R = Rust `cargo test`, Py = pytest, Sw = Swift kit/macOS host, V = Vitest, PW = Playwright.

**CI caveat (applies to the starred tests):** `rust/crates/bb-client/tests/{protocol_faults,e2e_backend,hints_backend}.rs` return early when no backend interpreter is found. CI's `cargo test --locked` does not set `BB_BACKEND_PYTHON` or `BB_REQUIRE_BACKEND`, so these 25 tests pass in CI without exercising anything. They last ran for real at cf28db8d (rehearsal S2). HEAD has since changed `bb-client` storage, transport and execute.
