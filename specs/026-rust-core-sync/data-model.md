# Data model: shared core and synchronization

Status: proposed implementation contract; no migration or ADR approval is implied. [sync-v1](contracts/sync-v1.md) defines ordering/recovery; [command catalog](contracts/command-catalog.md) defines mutations. All paths below are repository-relative.

## Ownership and canonical fields

Tasks owns Tasks, Projects, Tags, subtasks/comments and the **complete native Review aggregate** in one server transaction. Identity remains the authority for owner/session/access generations; Capture, Organize, CRT and Execution retain their stores and ports (ADR-0001/0002/0027/0028). The server is authoritative for synced accounts. A device owns its durable intents, drafts and account-less workspace; its synced confirmed base is a replica. A device is never an owner.

Reuse `backend/app/modules/tasks/domain.py`, `review_domain.py`, `backend/app/schemas/{tasks,review}.py`, `specs/020-weekly-review/{data-model.md,contracts/http.md}` and `specs/021-mac-sync/data-model.md`. The accepted ADRs and field behavior take precedence over historical descriptions. This document adds replication metadata, not new GTD states.

Every server key includes `scope_id`, bound one-to-one to the existing `owner_id`. Foreign keys and unique names are scope-local. New native entity IDs are `<task|project|tag|subtask|comment>_<lowercase UUID>`; new Review IDs use the prefixes in sync-v1 §2. Existing IDs and old local→server aliases are preserved verbatim. New IDs must be tested against legacy path/reference validators before exposure. No timestamp/title matching establishes identity. A `record_key` is a JSON array of key components, avoiding delimiter collisions for composite keys.

Each replicated row has `(scope_id, entity_type, record_key, record_version)` plus the following payload. Existing `revision` fields retain their domain meaning and are the `edit_revision` referred to by preconditions; not every projection has one. New `record_version` increments on every changed serialized fact, including bookkeeping, and is never reused after deletion. All revisions, order keys and synchronization counters are decimal strings on sync v1, with lossless conversion to existing REST integer fields. Non-counter bounded enums/counts keep canonical types. UTC instants use RFC 3339; a due day stays `YYYY-MM-DD`; Review wall time stays `HH:MM` plus IANA zone.

`review_state`, noncaptured Review queues, open-task counts and formulation advisory instants are **derived queries** of the consistent replicated rows plus explicit current time/device zone and current capabilities. Their API output follows `ReviewStateResponse`/`QueueResponse`; do not persist a stale second authoritative aggregate. `server_now` is response timing metadata. Recompute time-dependent classifications on wake/time-zone change as well as data invalidation, without generating domain writes. The server stores private Undo/park snapshots required by accepted reducers; synced clients defer operations that require them as the current client does. Account-less local Review preserves its existing local Undo data and seven-day expiry, separately from server projections.

## Domain invariants and transitions

Task lifecycle remains Inbox/Next/Waiting/Someday ↔ explicit complete/cancel/reopen, with reopen destination required; only authorized auto-park automatically moves Next→Someday. Waiting requires the canonical waiting metadata. Project active↔archived preserves memberships and historical markers; newly assigning an archived project is refused. Tag deletion removes affected task links atomically. Child lifecycle and existing ordering remain unchanged; there is no new task-delete or manual reorder command.

Review session transitions remain `open → completed|completed_empty` on finish, or `open → partial|abandoned` on replacement/idle expiry, selected by qualifying activity. Progress merges/deduplicates, never generic CAS. Decision/Undo and bulk release/Undo retain ADR-0027 revision, eligibility, per-item skip, yield and retention rules. `record_version` does not substitute for those rules. Formulation bookkeeping preserves task edit revisions; the stalled count survives leaving Next. A deleted follow-up task from valid Undo emits its tombstone and dependent projection changes atomically.

## Server synchronization and work records

These are proposed logical tables; physical columns/indexes may follow the repository adapter. They are not a second domain store.

| Record / unique key | Required fields and constraints |
| --- | --- |
| Scope / `scope_id` | owner ID, server/feed/access generation, storage epoch, monotonically committed sequence. One locked scope counter allocates commit order in the domain transaction. |
| Device epoch / `(scope, device_id, epoch)` | status `active|closed`, registration/closure instants and reason. Registration never reopens closed IDs. Local `pending_registration` has no server authority. |
| Command receipt / `(scope, command_id)` | trusted writer origin, protected normalized-envelope fingerprint, accepted/rejected outcome, safe code, nullable mutation commit sequence, `has_changes`, result versions and response expiry; optional content-bearing result only within source TTL. A unique legacy `(owner, idempotency_key)` mapping spans legacy transports. |
| Change transaction / `(scope, commit_seq)` | transaction ID, source command ID, commit time, complete typed upsert/tombstone records; unique source command effect. Internal bookkeeping also has a stable effect/command ID. Rejected/no-op receipts do not manufacture domain transactions. |
| Snapshot / `(scope, snapshot_id)` | generation, watermark, immutable ordered pages, total records/bytes, manifest digest, absolute expiry/status. Pages and large-transaction transfer objects inherit source expiry/deletion rules. |
| Job/effect / `(scope, dedup_key)` | durable job ID/type, payload reference, run-at, status, attempts/max attempts, lease owner/until, monotonically increasing fence, effect command ID, last safe code/correlation ID. Current fence checked in the same transaction as result. |
| Restore control decision / immutable decision ID | minimal owner/entity IDs, purge/deletion or authority-revocation action, effective generation/time. Protected durable ledger outside task-backup rollback; replay before reopening access. Retain only while an affected restore point is recoverable (proposed backup/WAL horizon ≤7 days), then erase. Purge completion requires retiring affected restore points and erasing its owner-linked marker. |

Job states: `queued → leased → succeeded`; retryable failures/expired leases return to `queued` with bounded backoff, exhausted retries become `failed`, cancellation becomes `cancelled`. An external effect with an unknown outcome becomes `reconciliation_required` and cannot be blindly retried. Renewing a lease or retrying a job does not replace the effect command ID. No receipt, job body or control record is public domain data merely because it shares a DB.

## Local durable records and recovery

| Record / key | Contents and lifecycle |
| --- | --- |
| `confirmed_records` / `(workspace, type, record_key)` | Public records plus final tombstone versions for current base. Changed only by full feed transaction or snapshot activation. |
| `outbox` / `(workspace, command_id)` | Immutable envelope, epoch/local sequence, dependencies, state, ever-sent/attempt/timing metadata, superseded link. Payload and IDs survive crashes and resets. Index dependency IDs and runnable order. |
| `command_receipts` / `(workspace, command_id, server_generation)` | Verified receipt; no receipt from an old generation proves inclusion in the current base. |
| `sync_issues` / `(workspace, issue_id)` | command ID, typed reason, local intent/text, shown base revision, dependent IDs and resolution state. No auto-expiry of unresolved work. |
| `drafts` / `(workspace, draft_id)` | editor kind/record reference, locally authored fields, base revision and update instant; not a network command. Incoming data does not replace them. |
| `sync_meta` / workspace | schema/storage epoch, account link, all request-generation fences, device/intake epoch state, next local sequence, cursor/base watermark, projection generation, last successful pass. |
| `identity_aliases` / `(workspace, entity_type, old_local_id)` | Proven legacy server ID and provenance. Aliases never cross owner/workspace boundaries; no heuristic merge. |
| Staging base / activation ID | Snapshot/large-transaction manifest, received page bitmap/digests, target generation/watermark. Never the UI's active state until complete and valid. |

`queued → sending → unknown` on lost response; retry retains the envelope. Accepted with changes becomes `accepted_awaiting_feed`, then leaves pending only with current-generation feed/snapshot inclusion proof. Accepted no-op completes from its receipt. Terminal rejection becomes an issue; descendants become `blocked_dependency`, independent commands continue. Dropping/replacing a rejected intent is an explicit resolution; uncertain effects must first be reconciled. A receipt arriving before a feed does not overwrite the confirmed base.

One interprocess lock/SQLite write transaction covers enqueue+projection+sequence, feed+cursor+replay, and snapshot activation. Activation reads the **live** queue, issues, drafts and intake epoch under that lock, not copies captured when download started. Explicit epoch closure preserves old unknown envelopes and atomically creates a new durable pending-registration epoch with the next genuinely new gesture. Ordinary cursor reset preserves an active epoch. Account-less work never gets sent until the existing explicit account-link choice has been recorded. Account-less gestures are durable local commands, not already-authorized server envelopes with a fictitious scope. Explicit merge constructs and durably records new owner-bound import commands from that workspace and its proven IDs/aliases; once remotely enqueued their envelopes are immutable. The link checkpoint records which local records were included so a crash cannot create a second import. Previously sent or uncertain account commands are never relabeled as account-less imports or moved to another owner.

## Retention, deletion and export

Domain records and decision history follow their existing accepted policy; this feature invents no task/history auto-delete. Content-bearing task/Review **command responses** expire after 24 hours; content-free protected receipt metadata lasts until account purge. Capture's existing commit-recovery exception and CRT's separate policy do not expand ordinary receipt TTL. Decision Undo/task-before and bulk clock-before content expires at its original seven-day deadline. Park clock-before retains its existing source policy; it is not made a new seven-day record by this spec.

Feed retention is proposed 90 days, snapshot and oversized-transaction transfer TTL 30 minutes. Neither extends source content life. Expired/deleted content is unavailable immediately on reads; independent retention work removes/redacts copies and invalidates immutable transfers. Purge removes scope data, receipts, transfer objects and jobs, and retires/removes affected backup/WAL/transfer artifacts before reporting completion, then erases its owner-linked control marker. A deletion/revocation ledger entry is not an indefinite exception to `docs/data-retention.md`; keep it only until the affected restore points expire or are made irrecoverable. If artifact removal cannot be proved, purge remains incomplete and access stays closed. Local queues/issues/drafts remain until proven completion, explicit resolution or the existing warned account/device deletion policy; they are never silently aged out during recovery.

Export includes domain/user-authored local data under existing export boundaries, including decision reasons and account-less data where supported. Exclude fingerprints, secret/session material, lease tokens and protected control/dedup records from a safe content export. Diagnostics contain only approved safe IDs, codes, timing and counts; never payloads, text, media or hashes.
