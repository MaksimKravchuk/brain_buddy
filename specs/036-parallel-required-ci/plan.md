## Contracts and failure handling
scripts/ci_shards.py is standard-library control/manifest code; only the context-union verification operation imports the existing coverage tool after aggregator installation. Pytest plugin hooks use passed objects without importing pytest for utility tests. CLI operations: backend collection manifest/argument generation; backend result/manifest merge validation and diagnostic copying; mutation scope selection; mutation per-shard result recording; mutation aggregate validation/summing. Pass paths explicitly and candidate SHA/index/count through arguments/environment. Reject malformed/missing/duplicate indexes, inconsistent collection or source/mode, incomplete/overlapping assignments, mismatched JUnit counts, XML failures/errors, wrong scope/files, overlapping mutant identities, invalid totals or interruption. Shard uploads run with always(). Aggregators download available diagnostics, publish canonical diagnostics before failure checks, and fail on missing/failed/canceled/corrupt parts; an absent dependency never suppresses the judge. Missing uploads/downloads fail. Artifacts contain synthetic test IDs, compiler/test outputs and counts only; no credentials, user content or account data. No new retention policy (reuse PR 7 days, others 30). No account export/purge impact for source-derived CI evidence.
