Owner decision 2026-10-14 · every new account needs an invite (FR-007)

Invite step for a new identity

When email-code, Apple or Google sign-in completes for an identity with no account, the server answers INVITE_REQUIRED with an opaque, single-use, short-lived pending handoff. Nothing has been created yet. The existing sign-in surface then asks for an invite code and resubmits. An existing account never sees this step. Password signup keeps its existing “Invite code” field. The Mac (D-05) offers password sign-in only and can't create accounts, so it has no invite step. iPhone on the left, web on the right. Buttons are illustrative.

M-03 / D-04 · .01 Enter your invite code

Focus lands on the field. Enter or Return submits. Cancel abandons the handoff; nothing is created.

M-03 / D-04 · Other states

.02 · Submitting

Field read-only. Web: the existing Spinner after 300 ms. iPhone: the existing busy indicator.

.03 · Invalid or used code

That invite code isn't valid or has already been used. Check it and try again. Reference: demo-027-invite-01

iPhone: “Reference ID: …”. The same wording covers invalid and used codes. Focus returns to the field.

.04 · Handoff expired

This sign-in has expired. Start again to create your account.

Nothing was created; the invite isn't used.

.05 · Offline

Existing network error; the code is kept. iPhone: “Your local tasks are kept. Connect to the internet to sign in.” If the handoff expires meanwhile, the next try shows .04.

.06 · Existing account

No invite step. Sign-in completes as today.

.07 · Too many attempts

Too many requests. Try again in a few minutes.

.08 · Update required
