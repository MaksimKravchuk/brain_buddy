# Исправленный план CLI — решение перед реализацией

Статус: принято владельцем2026-10-06 ответом «Делай» на прямой вопрос о переходе к реализации. Полная запись: founder-acceptance.json. Срок до2026-10-20.

Результат: Rust-бинарник bb, компактный JSON и выбор полей, команды задач/проектов/тегов/деревьев и универсальные операции рабочего API; готовые сборки Linux x64/ARM64, macOS15+ x64/ARM64 и Windows x64; установка одной командой. bb auth login использует общий вход Google/Apple/email/пароль через браузер, поддерживает другой браузер для SSH и выдаёт отдельную защищённую сессию CLI.

Исправленный [план](../plan.md) и [ADR-0029](../../../docs/decisions/0029-runtime-managed-cli-authentication.md) используют единую SQLite-авторизацию из опубликованной работы modern-auth. Существующие задачи, права аккаунта и провайдеры сохраняют свою серверную логику. Все найденные технические замечания закрыты в ограниченных проверках исправлений; исходные отрицательные вердикты сохранены.

Предлагается founder acceptance только для реализации и тестирования в изолированной ветке, действующее до2026-10-20 включительно. Это честное закрытие двух кампаний с ограничениями, а не переименование их первоначального результата в approved. Основание: проверяющие работают в текущей сессии после отказа владельца от второго входа; их происхождение не подтверждено независимыми провайдерами. Компенсирующие меры:

- Проверить атомарный обмен, отзыв Google/Apple, версии аккаунта, удаление, отсутствие утечек и сохранение действующего подключения при ошибках; выполнить обязательные тесты/CI, отдельные review/QA для конкретного коммита.
- Публиковать каждый платформенный архив только после его нативной проверки и проверки установщика; Linux-проверка не заменяет macOS/Windows.
- Подключать серверную часть к уже интегрированной общей авторизации. Релиз CLI требует завершённой миграции modern-auth и совместимого образа для отката, затем отдельной безопасной активации CLI.
- Представить конкретные сборки и коммит для обязательного решения о production/release по правилам репозитория.

При подтверждении сохраняются настоящее лицо/дата, оба исходных результата кампаний, финальный digest, ограничения, меры и срок принятия. До подтверждения поле принятия остаётся незаполненным. Это не доказательство готовых сборок, настроенных провайдеров, успешного production-релиза или опубликованного установщика.
