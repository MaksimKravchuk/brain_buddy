## Path Conventions

- **Backend**: `backend/app/` (layered `api/` → `services|modules/` → `repositories`), tests in `backend/tests/`, vendored third-party runtimes in `backend/vendor/` (outside every lint, type and coverage scope)
- **Web**: `frontend/src/` with Vitest suites in `frontend/src/**/__tests__/` and Playwright in `frontend/tests/e2e/`
- **Mobile**: `mobile/src/` with Jest suites in `mobile/src/**/__tests__/` and the real-backend harness in `mobile/integration/`
- **Feature ids**: every task names the feature-qualified requirement ids it serves (`014-FR-###`, `014-SC-###`, `014-AC-###`); every test task names the exact test file and the ids its test names or Allure stories carry, because `scripts/check_requirement_coverage.py` traces only `014-FR-###`/`014-SC-###` (or `014_FR_###`/`014_SC_###`) markers and AC ids go into docstrings as in 007
- **Design ids**: every UI task names the `design.md` state ids (`D-##-S##`, `M-##-S##`) it realises; the acceptance auditor traces criteria through them
- **Lanes** (plan.md "tasks.md convention"): the frontend lane and the mobile lane are `[P]` against the backend a2a/observer lane; the removal/migration pass on `service.py`, `domain.py`, `repository.py`, `headers.py` and `secrets.py` is sequenced after the a2a/observer tasks on the same file and is never `[P]` against them (one ordered pass per file); vendoring plus `test_vendor_provenance.py` is `[P]`, while the two reference-runtime test modules are gated on the whole §1–§4 pipeline. `[P]` is granted conservatively: a task touching a file that more than one story or lane edits (`service.py`, `domain.py`, `repository.py`, `schemas/agents.py`, `api/agents.py`, `observer.py`, `container.py`, `main.py`, the rewritten backend suites, the shared client `types`/`client`/`hooks`/`copy` modules and the run-surface components) is not `[P]`, even inside its own phase
- **Human-only steps that are not tasks**: the attended Hermes live run (`quickstart.md` §8, spends provider money, approval-gated like `verify-live`), turning `external_agent_relay` ON, landing, deploy and the TestFlight/App Store release. They are release steps in `docs/external-agent-relay-release.md`, never work the implementer performs
