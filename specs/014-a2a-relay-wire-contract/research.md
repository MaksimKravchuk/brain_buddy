## Decisions

### A. A2A client strategy

- **Decision**: In-house minimal JSON-RPC 2.0 client in a new package `backend/app/modules/agents/a2a/` (`card.py`, `client.py`, `types.py`, `mapping.py`) built on the existing `validate_destination` + `pinned_request` (`egress.py`). **a2a-sdk is not a runtime dependency.** `a2a-sdk[http-server]==1.1.2` is added only to the `dev` extra in `backend/pyproject.toml` because the helloworld reference runtime (Decision G) needs it in the test interpreter.
- **Rationale**: (1) FR-004 pinning: the SDK transport builds `POST <interface url>` on an `httpx.AsyncClient` and the card resolver does `httpx_client.get(url)` (F8); pinning would need a custom `httpx.AsyncBaseTransport` that rewrites the URL host, injects `sni_hostname`, refuses redirects and caps bodies — replicating `pinned_request` inside an async stack the synchronous services and observer threads would have to drive through private event loops. (2) Error fidelity: the SDK collapses 401/403/429/5xx into `A2AClientError` text (F8), while FR-002/SC-009 need distinct categories. (3) Leniency: Hermes serves a legacy-shaped card (F5) that the SDK's `parse_agent_card` tolerates only through compat shims; our parser ignores unknown fields and accepts both shapes explicitly. (4) Weight: protobuf + google-api-core + json-rpc enter `pip-audit` (`ci.yml` "Audit Python dependencies") for six methods we can express in ~300 lines of strict, bounded Pydantic models (`StrictBaseModel`, `app/schemas/common.py`). (5) mypy `strict` (`pyproject.toml` 97–100): generated `a2a_pb2` types are opaque `Message` objects; our models are typed.
- **Pin consequences**: `httpx>=0.25,<0.29` admits the SDK's `httpx>=0.28.1`; adding the dev extra re-resolves `uv.lock` from 0.27.2 to 0.28.x for **all** environments (one lock). `egress.py` uses only `httpx.Client(timeout, follow_redirects)`, `client.stream(..., extensions=)`, `response.iter_raw()` — all present in 0.28; `httpx.MockTransport` (tests) and FastAPI `TestClient` are unaffected. Task: re-lock and run the full backend suite once before any feature work.
- **Alternatives**: full SDK client with custom transport (rejected: async/pinning/error-fidelity above); `a2a.types` only for validation (rejected: protobuf `ParseDict` is strict, so Hermes' extra `stateTransitionHistory`/`url` fields fail without the SDK's compat layer, and it still costs the protobuf stack for no runtime benefit).

### B. Background observer

- **Decision**: New `backend/app/modules/agents/observer.py` — `AgentObserver` owning a `ThreadPoolExecutor(max_workers=agent_relay.observer_workers, default 8)` for **exchanges** (blocking `SendMessage` for start and reply, `CancelTask`, `CreateTaskPushNotificationConfig`) and one scheduler thread (`agent-observer`) that every `observation_interval_seconds` (default 60) selects every dispatched, non-terminal, non-disconnected, task-known-or-exchange-open run across all owners (repository query with `next_observation_at <= now`), submits one `GetTask`/`ListTasks` observation per run (coalesced by an in-process `set` of in-flight run ids), and also drains a wake queue fed by verified pushes and command acknowledgements. Correctness never depends on memory: the run row carries `exchange_state (none|open|closed|interrupted)`, `exchange_started_at`, `exchange_deadline_at`, `next_observation_at`; at startup `recover_interrupted_exchanges()` flips every `open` exchange to `interrupted` (no thread survives a restart) and the first scheduled observation resolves it by `ListTasks(contextId)` — adopt if found, else `delivery_unconfirmed` (Decision C).
- **Dispatch shape**: the API thread (`dispatch_run`) keeps the 007 durable reservation, marks `delivery_unconfirmed` + `exchange_state=open` (F11), submits the `SendMessage` exchange to the pool, waits up to `dispatch_wait_seconds` (default 5) for the future; if the exchange is still open it performs **one inline probe** (`ListTasks(contextId, pageSize=5)` under the short timeout) and returns. Probe or exchange evidence upgrades `dispatch_state` to `sent`; a `ConnectError`/4xx before any task → `not_sent` (429 → `a2a_rate_limited`); anything ambiguous stays `delivery_unconfirmed` with the exchange open. The exchange's read timeout is `reply_window_seconds + 15 s` (default 300+15) so an agent answering at exactly the window is still received (SC-006). Reply exchanges reuse the same path with `command_id` as `messageId`.
- **Shutdown/Fly**: scheduler stop event + `executor.shutdown(wait=False, cancel_futures=True)` joined with a 5 s timeout in the existing `_stop_maintenance_sweeps` handler (`main.py` 230–238); in-flight exchanges are recovered on restart as above. F10: one always-on machine, 8 threads and ≤ 8 open sockets are negligible at 1 GB; no per-run thread exists, so "no per-owner cap" (spec Assumptions) is bounded only by the pool and `sensitive_action_rate_limiter`-style limits on the API side.
- **Determinism in tests**: `AgentObserver(executor=SynchronousExecutor(), clock=Clock, probe_delay=0)` runs exchanges inline; `observer.run_once(now)` performs one scheduler pass; no test sleeps. The thread is started only by `main.py` under `background_maintenance_enabled` (F9), which the compose E2E already enables.
- **Alternatives**: per-run threads (rejected: unbounded, Fly 1 CPU); asyncio task inside uvicorn (rejected: services are sync, ADR-0002 forbids correctness on untracked `asyncio` tasks); polling only from the maintenance thread with no held exchange (rejected: Hermes never creates a task without the blocked request, F1/F2); streaming `SendStreamingMessage` (rejected: doubles the transport surface, adds nothing over probe+poll, and `stateTransitionHistory` is absent on Hermes).

### C. Dedup and identifiers

- **Decision**: `context_id = run.id`; start `message_id = f"{run.id}:start"` (derived from the run's idempotency key, which 007 already equals to the run id — `service.py` 1506); reply `message_id = command_id`; cancel carries `CancelTaskRequest.metadata["brainbuddy.command_id"]`. Every message carries `metadata = {"brainbuddy.task_id": <task id>, "brainbuddy.run_id": <run id>}` (FR-006). Before **any** resend (replayed confirmation on a `delivery_unconfirmed`/`interrupted` run) BrainBuddy calls `ListTasks(contextId=run.id, pageSize=5)`; a found task is adopted (newest by `status.timestamp`) and never resent; only an empty answer allows resending the byte-identical message. Under a guaranteed-tier agent the resend additionally carries `A2A-Extensions: <uri>` and `message.extensions=[<uri>]`; the agent dedups by `(contextId, messageId)`.
- **Extension identifier**: `https://github.com/MaksimKravchuk/brain_buddy/blob/main/docs/a2a-extensions/single-start/v1.md` (repo remote per `git remote -v`; A2A `docs/topics/extensions.md` asks for a versioned URI whose specification is hosted at the URI). Contract in `contracts/brainbuddy-single-start-extension.md`; tier = `guaranteed` iff the URI appears in `card.capabilities.extensions[].uri`, else `best_effort`. Accepted for v1 (Resolved 5): the path is frozen by repository policy; a redirect-based identifier may be added in a later version without changing v1.
- **Rationale**: spec §3.4.1 lets an agent accept a client `contextId` (Hermes and the SDK do, F2/F6); `ListTasks` is a core operation with a `contextId` filter in both runtimes; replays of the same `Idempotency-Key` never reach the network at all (F11), so SC-002's three replays create one task on every runtime, extension or not. Residual duplicate risk (Hermes forgets tasks on restart, F3) is disclosed, not hidden (FR-003).
- **Alternatives**: `message_id = run.id` (rejected: replies need distinct ids and the extension dedups per message); a2a `referenceTaskIds` for replies (kept as an additional hint only); client-generated task ids (not allowed by §3.4.2).

### D. Push notification receipt

- **Decision**: New inbound route `POST {api_prefix}/a2a/push/{run_id}/{token}` replaces `/agent-events`. BrainBuddy registers, **inline in `SendMessage.configuration.taskPushNotificationConfig`** whenever the card declares `pushNotifications: true`, `{url: "<public_base>/api/a2a/push/<run_id>/<token>", token: <token>}` (Hermes stores only the URL, F4; the SDK echoes the token in `X-A2A-Notification-Token`, F6 — the path token works for both). `CreateTaskPushNotificationConfig` is used only for a task adopted after an interrupted exchange. The token is 32 random bytes per run, stored only as `SecretBox.fingerprint` (`push_token_fingerprint`); verification = path token fingerprint match against a dispatched, non-terminal, non-disconnected run whose connection still exists. A verified push enqueues an immediate observation and answers `204`; **the body is never parsed for state** (read up to 64 KB for the cap, then discarded). Unverified/unknown-run/oversize/malformed → opaque `403`/`413` with **no durable row** (007 post-ratification clarification, `specs/007-external-agent-relay/spec.md` 111–128); a known run with a wrong token records one bounded row per (owner, connection, `push_token_rejected`, UTC day) exactly like `_audit_authenticated_event_rejection`. The route is rate-limited per run id with an `InMemoryRateLimiter` (`app/core/rate_limit.py`).
- **Rationale**: FR-008 says push only accelerates observation, so the token is a capability to trigger one authenticated `GetTask`, nothing more — acceptable in a URL that Hermes may log. Hermes' `X-A2A-Signature` is keyed by `A2A_PUSH_SECRET` (unknowable) or the bearer token (F4); it is not per-run and is therefore **not** accepted as verification; a Hermes push without a path token is simply not accelerated and SC-006 still holds through the 60 s schedule.
- **Alternatives**: verifying Hermes' HMAC with the stored credential (rejected: not per-run, couples to one agent's convention); registering `authentication: {scheme: Bearer}` (kept optional; neither runtime honours it); parsing the payload to short-circuit `GetTask` (rejected: FR-008 forbids state from push).

### E. State mapping and observation versioning

- **Decision**: `mapping.py` is a pure function `project_observation(task_or_message, *, now, limits) -> Observation`: `TASK_STATE_SUBMITTED → accepted`; `WORKING → running` with `progress_text` = text parts of `status.message` (≤ `MAX_PROGRESS_CHARS` 2000); `INPUT_REQUIRED → blocked` with `question_text` (≤ 4000); `AUTH_REQUIRED → blocked` with `failure_reason=None`, `question_text=None`, fixed `blocked_reason="Agent needs additional authentication"` and `needs_user=False`; `COMPLETED → completed` with `result_text` = text-part artifacts joined by blank lines then the final status text (≤ `MAX_RESULT_CHARS` 20000), `result_link` = first `Part.url` (inert per `egress.interactive_result_link`), non-text parts → `artifacts_summary[{name, media_type, kind}]` (≤ 20 entries) rendered as placeholders; `FAILED → failed` with `failure_reason` = status text; `REJECTED → failed` with `"Rejected by agent" + (": " + status text)`; `CANCELED → cancelled`; a direct `Message` answer → `completed` with its text. Truncation appends `" … [truncated]"` and still accepts the observation. `TaskNotFoundError (-32001)` on `GetTask` → `agent_task_missing_at=now`, last contact preserved, observation stops, reply/cancel withdrawn, `reported_state` unchanged (AC-020). **Task succession** (Resolved 6): when a reply exchange returns a Task whose id differs from `agent_task_id` but whose `contextId` equals the run's correlation id (Hermes mints a new task per message, F2, and its watchdog fails the original after 300 s, F3), BrainBuddy adopts the returned task as the run's current agent task, appends the timeline event "Agent continued the run in a new task" carrying the old and new task ids, and never refuses the reply.
- **Versioning**: the observer reads `run.run_version` as `based_on`; under the owner `command_lock` it applies only if `run.run_version == based_on` (compare-and-set) and writes `run_version = based_on + 1`; an identical observation (same state and texts) bumps `last_contact_at`/`last_observed_at` only and appends no timeline event; a differing observation appends an `AgentRunEventDocument` with `trigger ∈ {dispatch, schedule, push, command}`. Terminal states lock the run: it leaves the schedule and any later differing observation is rejected (`observation_rejected: run_terminal`, bounded audit).
- **Alternatives**: trusting `status.timestamp` ordering (rejected: absent/unreliable, spec has no version); treating `INPUT_REQUIRED` as terminal for Hermes because the watchdog fails it at 300 s (rejected: the observation of `FAILED` will arrive honestly).

## Resolved (product-owner decisions at design sign-off, 2026-09-03; spec commit `9afdcaf`)

1. **Vocabulary** — client-facing fields are `supporting_items` (was `context_items`) and `correlation_id` (the A2A `contextId`); the protocol words never appear in client-facing responses (spec Clarifications, FR-014). Both clients are rewritten anyway; internal Python/JSON-RPC names keep the protocol terms.
2. **Link** — the best-effort disclosure links to the published extension specification (FR-003, AC-026): `tier_disclosure_url` on the connection response and on the hand-off preview response; opens only on explicit user action.
3. **Agent changed** — a fifth connection condition (FR-002, FR-014): `status="untested"` + `last_test_error_code="agent_card_changed"` + `agent_changed: true`, rendered as D-01-S20 / M-01-S18; behaves as untested until a new successful test and requires reauthentication before the next content-bearing dispatch (FR-004).
4. **One-time acknowledgement** — not warn-only (FR-003, AC-026): per-connection `best_effort_acknowledged_at`, set by the first confirm carrying `acknowledge_duplicate_risk: true`; a confirm without it while the timestamp is null on a best-effort connection is refused; the preview exposes `acknowledgement_required`.
5. **Extension identifier** — the GitHub URI is accepted for v1; the path is frozen by policy and a redirect-based identifier may be added in a later version without changing v1 (`contracts/brainbuddy-single-start-extension.md` §8).
6. **Task succession on Hermes** — accepted: a reply that returns a new task in the same correlation context is adopted as the run's current agent task, the timeline records "Agent continued the run in a new task" with the old and new ids, and the reply is never refused (Decision E, `contracts/a2a-wire.md`).
