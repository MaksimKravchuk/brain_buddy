Preserve task fields, API filters, server order/pagination, safe saves and explicit reopen. No new API, storage metadata, search/filter capability or flag registry.

## Implementation

In `frontend/src/features/tasks/TaskListPage.tsx`, request includeCompleted=true through the existing endpoint and retain includeCancelled opt-in. Partition flattened fetched tasks into open groups first, one Completed section and optional distinct Cancelled history. Preserve server order within each partition; detail previous/next navigation follows rendering. Render terminal headings only for nonempty sections. Preserve open-only sidebar and subtitle counts using existing counts_by_state.

Retain the existing mixed 50-row server page budget and Load more behavior. Every fetched completed task is rendered, with no recency/count cutoff. An unfetched open row may require loading another page; once fetched, it joins the open section. No server ranking, dual query, retention cache or origin metadata is introduced. Existing summary batch limits remain unchanged.

Capture current row rectangles immediately before a validated canonical completion updates list/detail cache. Reuse the existing autosave acceptance mechanism for list and detail completion. In `frontend/src/features/tasks/useTaskCompletionAnimation.ts`, a layout effect and Web Animations API move matching real rows from old to final positions over 380ms, matching task ids across grouped parents. Animate displaced rows, without duplicate DOM rows or forced scrolling. Initial fetch, navigation, loading more and refetch alone do not trigger movement. Failed/pending saves keep open position and styling.

Concurrent canonical successes start from the current visual positions, replacing only prior visual animations. Each saved task appears once; failed saves stay open. Displaced controls remain hit-testable at their visual transformed position. Add a local pending-id guard and disabled completion control until the existing save settles, preventing repeated taps from queuing duplicate completion barriers; retain the existing autosave/recovery mechanism. Reduced motion gives immediate final placement. Web Animations API is part of the supported browser baseline; avoid a conflicting silent no-motion fallback. If completion removes the focused button, focus that row's title link with preventScroll; preserve detail-sheet focus behavior. Grey text is not multiplied by whole-row opacity. Animation never delays persistence.

Task-list cache isolation is limited to the newly widened list payload: `frontend/src/api/taskHooks.ts` adds a captured account-and-origin scope to task list keys, and canonical list patches use that same captured scope. Do not change authentication protocols, routes or the server authorization model. A late save from an old session must not write into the current account's list or animate its rows. Existing broader cache cleanup is outside this UI task.

Filtered lists are overlapping query results, not exclusive task containers. Apply a canonical task update by task id to every cached page in the captured account/origin scope that already contains that id, then invalidate the existing query family to re-evaluate membership. Never append the task blindly to unrelated filters or create per-list task statuses. Partition each returned view independently. Animate the visible completion interaction; opening another matching view shows the saved section without replaying the animation.
