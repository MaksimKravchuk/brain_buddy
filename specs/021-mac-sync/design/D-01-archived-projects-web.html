D-01 · Archived projects with unarchive (web)

The web can archive a project today (sidebar › project options › "Archive", no confirmation) but has no list of archived projects and no unarchive: an archived project simply disappears. With ADR-0020 (FR-024 – FR-027) archive keeps every task's project, so the archived project needs a place and a way back. Placement (left open by the spec): a collapsed "Archived projects" disclosure at the end of the sidebar's Projects section, the same place the Mac uses, opening each archived project at its normal /projects/:id route with an "Unarchive" button.

Copy check: no web string says archive detaches tasks (verified in AppShell.tsx and TaskListPage.tsx), so the only web copy change is additive. The web stays online-only with no sync status (spec Assumptions); failures use the existing inline notice with the correlation ID.

Keyboard and screen readers

  • The disclosure is a button with aria-expanded and the accessible name "Archived projects, 2". Its expanded state is remembered per browser.
  • Tab order on the project page: heading → Unarchive → task rows. "Unarchive" has the accessible name "Unarchive Old flat". After success, focus moves to the heading and the toast is announced (role="status").
  • The archived row's options popover follows the existing popover rules: Esc closes and returns focus to the options button.
  • Contrast: slate-500 muted archived rows on slate-50 are 4.6:1; the chip's slate-600 on slate-100 is 6.9:1.
