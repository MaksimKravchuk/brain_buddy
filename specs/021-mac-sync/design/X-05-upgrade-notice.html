X-05 · One-time upgrade notice, only when the old store can't be read (macOS)

The normal upgrade is silent: on first launch after the update, every record of local-gtd.json is carried into the new local workspace (FR-020) and the old file is kept untouched until the new workspace is verified, then kept as a backup (FR-021). The person sees their tasks as before and the account-less footer (US4-1, US4-2). Nothing says "upgraded".

Only when the old file cannot be read (corrupt, or written by a newer version) does the Mac speak, once, in plain words, saying where the file is, and only then start with an empty workspace (FR-022). An app-modal alert at launch, before the workspace opens; the old file is never overwritten or deleted. This is one of the four dialogs FR-017 allows.

Behaviour

  • Once: shown at the first launch that finds the unreadable file. "Continue" or "Show in Finder" records it as seen. Quitting the app while the notice is open (interrupted) means it was not seen, and it appears again at the next launch.
  • Show in Finder reveals the file with it selected and closes the notice; the workspace then starts empty, as with Continue.
  • Never offered: delete, overwrite or "try again" on the old file. The app does not touch it (FR-022).
  • Keyboard and VoiceOver: focus on "Continue" (default, Return). Tab reaches "Show in Finder". VoiceOver reads the title, the message and the path on open. Esc is not mapped, because the notice must be read once; Return continues.
  • Partial read (some records readable, some not) is treated as unreadable: nothing is half-imported, and the whole file is kept (n/a as a separate state).
