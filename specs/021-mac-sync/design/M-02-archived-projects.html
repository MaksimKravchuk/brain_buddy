M-02 · Archived projects with unarchive (iOS)

Today the iPhone's archive is one-way and detaches tasks: the confirmation says "Its tasks stay in their lists but lose the project. You can't undo this.", and the Archived projects screen is read-only ("can't be restored"). With ADR-0020 on the server (FR-024 – FR-027), archive keeps every task's project, an archived project opens and lists its tasks, and it can be unarchived. Placement (the spec left it to this stage): where archived projects are already listed, the existing Lists hub "Archived" row → Archived projects screen, with "Unarchive" as a swipe action and in the project's toolbar.

Archive is no longer destructive, so it loses the rose tint and the destructive role; the confirmation stays (it is today's behaviour) with honest copy. Example: "Old flat" archived with 3 open tasks.

VoiceOver, touch, loading

  • Archived rows: "Old flat, archived, 3 open tasks". Custom action "Unarchive" on each row (the swipe action), so it is reachable without swiping. Toolbar button: "Unarchive Old flat".
  • Swipe actions and the toolbar button are 44 pt targets. Unarchive has no confirmation: it is reversible by archiving again.
  • Loading: n/a, the iPhone reads its local store. Offline: works, queued (FR-008).
  • An older iPhone build still archiving the old way keeps working; the server applies the new semantics whichever client archives (edge case). Those builds show archived projects read-only until updated.
