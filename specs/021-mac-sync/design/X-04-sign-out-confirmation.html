X-04 · Sign-out confirmation (macOS)

Started from "Sign out…" in the status popover (X-02) or the app menu (X-07). Signing out returns the Mac to an empty, account-less workspace and removes the account's data from this Mac (US1-6). With unsent changes it warns with the count and offers exactly two choices, as the iPhone does (FR-018): keep them (Cancel) or sign out and remove them. A window-attached alert sheet; Cancel is the default button so Return and Esc are both safe. If the task editor or capture field holds unsaved text, the app's existing "discard your edits?" question comes first.

Wording is the iPhone's (SettingsScreen.swift, WorkspaceError.unsyncedChanges) with "Mac" for "iPhone". The Waiting / Someday / Project review marks stay on this Mac across sign-out (FR-023); the old store backup is kept per FR-021. Neither is mentioned, because neither is lost.

Keyboard and VoiceOver

  • Focus on open: "Cancel" (default). Return and Esc both cancel. Tab reaches "Sign out and remove"; Space activates it.
  • VoiceOver reads the title and the message on open. Closing returns focus to the status words in the sidebar footer (X-01).
  • Loading: none. Sign-out is local and immediate; an offline logout is queued (FR-005).
  • As delivered (2026-10-08): "Sign out and remove" removes only the changes this alert named (by id and content). If any other change is pending at confirm, nothing is removed and the alert shows again with the real count. Edits made while the sign-out runs are refused with words and keep the typed text. Open sync issues are named the same way: an issue the alert did not name, or a named change the server rejected meanwhile, refuses too. Quitting the app waits for the removal.
