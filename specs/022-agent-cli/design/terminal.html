BrainBuddy in your terminal

Proposed interface · D-01, D-02 and D-03 · synthetic data only · no published release yet

Sign in once through the shared BrainBuddy login, then use one command per action. Compact JSON goes to stdout; structured errors go to stderr. No prompts during agent business work.

D-03 · Connect your account once

$ bb auth login
stderr: Opened the BrainBuddy verification page. Confirm code DEMO-1234.
browser: Sign in with a configured method, verify your account and approve this CLI connection.
{"data":{"authenticated":true,"server":"https://brainbuddy.example.test","account_id":"member-demo","credential_store":"os"}}

$ bb auth login --no-browser
stderr: Open the BrainBuddy verification link on another device and confirm code DEMO-5678.
The link and one-time code are shown only during explicit login.

$ bb auth status
{"data":{"authenticated":true,"server":"https://brainbuddy.example.test","account_id":"member-demo","credential_store":"os"}}

$ bb auth logout
{"data":{"authenticated":false,"local_cleared":true,"server_revoked":true}}

Expired/denied approval: no session replaced; explicit error.
Keychain unavailable: choose explicit protected-file storage or external secret input.
Offline logout: local access removed; remote revocation reported as unconfirmed.

This is proposed shared-auth integration. Provider availability comes from BrainBuddy; the current inspected server has no device authorization endpoint yet. Passwords and provider tokens stay out of the CLI.

D-01 · Capture, inspect, act

$ bb commands task
{"name":"task","commands":["add","list","get","update","transition"]}

$ bb task add --title "Call the garage" --idempotency-key garage-1
{"data":{"id":"task-demo","title":"Call the garage","state":"inbox","revision":1}}

$ bb task list --query garage --limit 20 --fields id,title,state,revision
{"data":[{"id":"task-demo","title":"Call the garage","state":"inbox","revision":1}],"page":{"has_more":false,"next_cursor":null}}

$ bb task update task-demo --revision 1 --json @- --idempotency-key garage-2
stdin: {"title":"Call the garage and book the repair"}
{"data":{"id":"task-demo","title":"Call the garage and book the repair","state":"inbox","revision":2}}

$ bb task transition task-demo complete --revision 2 --idempotency-key garage-3
{"data":{"id":"task-demo","title":"Call the garage and book the repair","state":"completed","revision":3}}

D-01 · Recover deliberately

Stale revision · stderr · nonzero exit
{"error":{"code":"conflict","status":409,"message":"Revision conflict","reference_id":"demo-reference","detail":{"current_revision":3}}}

Interrupted write · stderr · nonzero exit
{"error":{"code":"transport","message":"Request failed; delivery is unknown","delivery_unknown":true,"idempotency_key":"garage-3"}}

Reread before retrying a stale edit. Recover uncertain delivery using the same key and identical input according to the server contract. Credentials never appear in output or previews.
