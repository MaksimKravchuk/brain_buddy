## Method

A requirement with no design row is backend-only or governance-only; a requirement with no distinct SC row is verified as part of a broader outcome (noted inline).

## Known non-gaps (deliberately out of scope, not missing)

- No task exists for a CLI reset command, a cohort sweep beyond DD-9's purge
  call, a percentage/segment/schedule rollout, an audit store/history UI, or a
  generalized migration framework beyond the one bounded one-time migration —
  all are named in spec.md's Out of Scope section and their absence here is
  consistent with it, not an omission.
- `delivery_canary` has no lane-B or lane-C task that mutates it, by design
  (DD-1); B1/B8/F1 each include an assertion that it is *unaffected*, which is
  the coverage this analysis expects for an explicitly-excluded flag, not a
  gap. `.github/workflows/`/`scripts/` edits are **not** absent this time —
  G6–G8 name the narrow, DD-14/DD-15-bounded edits the correction requires,
  distinct from the original package's "deliberately untouched" claim.
